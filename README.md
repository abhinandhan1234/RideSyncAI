## Project Overview

RideSync AI is a full-stack, AI-augmented ride-hailing platform that solves the five core requirements of Problem Statement PS2:

- **Intelligent demand prediction** to dispatch drivers before passengers even open the app.
- **Zone-level surge pricing** and smart driver repositioning based on real-time supply/demand.
- **Multi-passenger ride pooling** that sequences pick-ups/drop-offs for maximum efficiency.
- **Weighted driver allocation** that balances proximity, workload and reliability.
- **Automatic reassignment** that keeps every ride moving when a driver rejects, times out, cancels or is significantly delayed.

On top of the mandatory five, the team is building three original features — **EcoDispatch AI**, **EcoRoute**, and **RideSync CityLab** — that push the submission beyond the baseline checklist.

---

## Belagavi Simulation Scope

All geographic data is anchored to **Belagavi (Belgaum), Karnataka, India**.  
The road network is extracted from OpenStreetMap via `OSMnx` and stored as a `NetworkX` directed graph (`belagavi_roads.graphml`).  
Demand data, driver positions and zone boundaries are **fully synthetic** — generated by scripts in `ai-engine/` — but use real Belagavi locality names and coordinates so that maps, routes and ETAs are geographically plausible.

> **Important:** This is a simulation, not a live deployment. No real user or operational data is used.

## PS2 Mandatory Features

1. **Predictive Demand Forecasting**  
   A Gradient Boosting Regressor trained on synthetic historical demand (time-of-day, day-of-week, weather proxy, zone features) predicts ride counts per zone per 15-minute slot. Predictions drive proactive driver dispatch and are visualised on the admin heat map.

2. **Zone Intelligence with Surge Pricing & Driver Repositioning**  
   Each zone is scored on a supply/demand ratio updated every minute. When a zone crosses the surge threshold, multipliers (1.0×–2.5×) are applied and idle nearby drivers receive repositioning nudges via Socket.IO push messages.

3. **Multi-Passenger Ride Pooling**  
   A route-insertion heuristic evaluates whether a new passenger request can be inserted into an in-progress or pending pooled ride without violating capacity (≤ 4 seats) or per-passenger detour limits. The resulting pick-up/drop-off sequence is re-optimised on every insertion.

4. **Intelligent Driver Allocation**  
   Each available driver is scored with a weighted formula that considers: GPS distance to pickup, estimated ETA (road-graph routing), active workload (rides today), historical acceptance rate, and idle time. The highest-scoring driver within the zone (or nearest zone) receives the first offer.

5. **Automatic Reassignment**  
   A state machine tracks every ride offer: `PENDING → OFFERED → (REJECTED | TIMEOUT) → REASSIGNING → OFFERED → …`. On rejection or offer timeout (configurable, default 20 s), the next-best driver is selected automatically. Cancellations and detected delays (ETA slip > threshold) also trigger reassignment, with the passenger notified via Socket.IO at every transition.

## Additional Innovations

### 🌿 EcoDispatch AI
Fuel consumption is estimated for each candidate driver using a simple per-vehicle-type model (L/100 km). The allocation scorer can be switched to **EcoMode**, which up-weights fuel efficiency so that the platform minimises total fleet fuel burn across a shift — not just individual ETAs.

### 🗺️ EcoRoute
When routing a driver or displaying a trip to a passenger, the system computes three alternatives via the OSMnx/NetworkX graph:
- **Fastest** — minimise travel time (congestion-weighted edge cost)
- **Shortest** — minimise total distance
- **Eco** — minimise estimated fuel consumption (distance × road-gradient proxy)

All three are presented side-by-side so the driver (or admin) can see the trade-offs.

### 🏙️ RideSync CityLab
An interactive browser simulation that runs the full dispatch algorithm against a configurable synthetic demand scenario. Users can toggle AI optimisation on/off and watch real-time metrics (wait time, utilisation, fuel) diverge between the AI-assisted and baseline (random assignment) strategies.

### ⛽ Fuel Economy Dashboard
An admin panel chart showing cumulative fuel consumption, per-driver economy scores, and projected savings from EcoDispatch over the current shift — updated via Socket.IO.

### 🌆 3D City Landing Page
A Three.js / React Three Fiber scene renders a stylised 3D Belagavi skyline as the app's landing page hero, with animated vehicle icons and a live demand heat-pulse effect.

## Local Setup

### Prerequisites

| Requirement | Version |
|---|---|
| Node.js | v18 or later |
| Python | 3.10 or later |
| MongoDB | 7.x (running locally or via Atlas) |

### 1 · Backend

```bash
cd backend
npm install
cp .env.example .env        # then edit MONGODB_URI, JWT_SECRET, etc.
npm run dev                 # starts Express + Socket.IO on :5000
```

### 2 · AI Engine

```bash
cd ai-engine
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# Download Belagavi road graph (first time only):
python data_gen/fetch_osm.py
# Generate synthetic demand data:
python data_gen/generate_demand.py
# Train demand model:
python demand_model/train.py
```

### 3 · Frontend *(teammate-owned)*

```bash
cd frontend
npm install
npm run dev                 # starts Vite dev server on :5173
```

> See `docs/TEAM_TASKS.md` for the full module ownership map.
